# DroneCAN 八口动力星型隔离 Hub 设计说明

**日期：** 2026-09-20  
**状态：** 已通过（2026-09-20）  
**应用：** 大型无人机 / ArduPilot + DroneCAN  
**产品定位：** 挂在飞控 **CAN1** 上的 **动力（ESC）专用** 星型隔离转发器  

---

## 1. 背景与目标

### 1.1 实机用法（用户现状）

飞控双 CAN 分工：

```
ArduPilot
 ├─ CAN1 ──►【动力 Hub】──► 电调支路
 └─ CAN2 ──►【外设 Hub】──► GPS / 空速 / 其它（本期不做，另板）
```

六轴共轴动力：

- **6 轴 × 每轴 2 电调 = 12 ESC**  
- **每 Hub 口挂 2 个 ESC**（同轴上下）→ 需要 **6 条电机支路**  
- **+1 口接飞控 CAN1** → 至少 7 口；本期做 **8 口**（多 1 路备份/调试）

### 1.2 本设计目标

实现一台 **8 路 Classic CAN 星型隔离动力 Hub**：

- 物理上：每路独立隔离（ADM3055E）  
- 逻辑上：**仅与飞控口互通**；电机支路之间不互相转发  
- 协议：DroneCAN / Classic CAN，默认 **1 Mbps**  
- 供电：**9–36 V**；收发：**ADI ADM3055E**（−40~105℃）

非目标（本期）：

- 外设 Hub（飞控 CAN2 侧）——二期同架构缩口即可  
- CAN FD 业务、支路互聊、异波特率网关  
- 替代飞控内 DroneCAN 协议栈

## 2.1 上位机口使能（新增确认）

用户通过上位机勾选实际使用的路数/哪些口参与转发，例如：

- 四轴共轴（8 ESC）→ 勾选 CAN_FC + M1…M4，关闭 M5/M6/X  
- 六轴共轴（12 ESC）→ 勾选 CAN_FC + M1…M6，X 可选  
- 台架只测两轴 → 只开 FC + M1 + M2  

**行为约定：**

| 项 | 约定 |
|----|------|
| 配置内容 | 每口使能/禁用；可选：口备注名、是否允许上行转发 |
| 未勾选的口 | 不转发；收发器建议进入 Silent 或关驱动，降低干扰与功耗 |
| CAN_FC | 建议强制保持使能（或禁止在 UI 关闭），避免整机失联 |
| 持久化 | 写入 MCU Flash 参数区，上电自动加载 |
| 连接 | USB（CDC 虚拟串口）或 UART；地面配置，**飞行中默认锁定不可改**（可设密码/拨码解锁） |
| 上位机形态 | **一期：Python 桌面小工具**（见 §6.1） |

不在一期范围：通过 DroneCAN 参数远程改口使能；正式 Qt/C# 量产工具（二期）。

## 3. 系统架构

### 3.1 框图

```
                    9–36 V ──► EMI/TVS/反接 ──► 宽压 DCDC ──► 5V_SYS ──► 3V3
                                                              │
         ┌────────────────────────────────────────────────────┤
         │                    STM32G474                       │
         │  FDCAN1 ── ADM3055E ── CAN_FC   飞控 CAN1 ★       │
         │  FDCAN2 ── ADM3055E ── CAN_M1   轴1 双 ESC        │
         │  FDCAN3 ── ADM3055E ── CAN_M2   轴2 双 ESC        │
         │  SPI ── 2518#1 ── ADM3055E ── CAN_M3  轴3         │
         │  SPI ── 2518#2 ── ADM3055E ── CAN_M4  轴4         │
         │  SPI ── 2518#3 ── ADM3055E ── CAN_M5  轴5         │
         │  SPI ── 2518#4 ── ADM3055E ── CAN_M6  轴6         │
         │  SPI ── 2518#5 ── ADM3055E ── CAN_X   备份/调试   │
         └────────────────────────────────────────────────────┘
```

### 3.2 端口分配

| 端口 | 控制器 | 用途 | 延迟优先级 |
|------|--------|------|------------|
| CAN_FC | FDCAN1 | 飞控 CAN1 上行 | 最高 |
| CAN_M1 | FDCAN2 | 轴1：2×ESC | 最高（片内） |
| CAN_M2 | FDCAN3 | 轴2：2×ESC | 最高（片内） |
| CAN_M3…M6 | MCP2518 ×4 | 轴3–6：各 2×ESC | 高 |
| CAN_X | MCP2518 #5 | 备份轴 / 台架调试 / 可静默 | 低 |

说明：若希望更多轴走片内口，可将「振动/负载更大」的轴优先分到 M1/M2。

### 3.3 与飞控双 CAN 的关系

| 飞控口 | 设备 | 本期 |
|--------|------|------|
| CAN1 | 本 8 口动力 Hub | ✅ 设计对象 |
| CAN2 | 外设转发器（采购件或二期自研） | ❌ 不在本板 |

## 4. 转发与故障策略

### 4.1 路由（硬性）

1. **CAN_FC 收帧** → 仅转发到 **已使能** 的 CAN_M1…M6 / CAN_X  
2. **已使能的电机/备份口收帧** → **仅**转发到 CAN_FC  
3. **禁用口**：不参与转发；不向该口发送  
4. **电机支路之间不转发**（轴与轴隔离）

### 4.2 装机含义

- 同一口上的 2 个 ESC 仍在**该支路短总线**上，可互相「听见」（同一物理段）。  
- **不同口**的 ESC 互不可见，只与飞控通信——符合动力隔离目标。  
- 飞控 DroneCAN 仍按 Node ID 分别访问 12 个电调。

### 4.3 故障切断

- 单口 TEC/REC 或错误帧超限 → Silent/关闭该路 ADM3055E，其它轴与飞控链路尽量保持。  
- CAN_X 可默认关闭，仅地面调试打开。

### 4.4 延迟

- 12 ESC @ 1 Mbps 流量集中在 CAN_FC，固件需保证 FC 口收发优先、队列有界。  
- M1/M2 用片内 FDCAN，降低两轴关键路径延迟。

## 5. 硬件要点

### 5.1 电源

- VIN **9–36 V** → 5V_SYS → 3V3  
- 8× ADM3055E 逻辑侧共 5V；CAN 侧由芯片 isoPower 自给  
- 输入：反接、TVS、EMI；功率按 8 路隔离收发 + MCU + 5×2518 留裕量  

### 5.2 ADM3055E ×8

- 温区 **−40~105℃**；工业级（非 AEC-Q100）  
- 布板遵循 **AN-0971**  
- 每路：TVS、可切换 120Ω；同口两 ESC 的终端按短支路规范设置  

### 5.3 MCU / MCP2518

- G474：3×FDCAN Message RAM 划分  
- **5×MCP2518FD**：SPI + INT；注意 CS/INT GPIO 数量与走线  
- 可用 1～2 组 SPI 总线挂多从设备；INT 建议独立或可屏蔽轮询+中断混合（实现阶段定）  

### 5.4 连接器

- CAN_FC：对接飞控 CAN1（线束按机型）  
- CAN_M1…M6：每口引出至对应轴两 ESC（建议口旁丝印轴号）  
- CAN_X：调试或第 7 轴扩展

## 6. 软件概要

```
初始化：8 口 1 Mbps；CAN_X 可默认 Silent
环：
  CAN_FC RX → 向已使能的 M1…M6、X 发送
  Mi / X RX → 仅向 CAN_FC 发送
  错误监控 → 单口切断 + FAULT 指示
配置通道：USB/UART ↔ 上位机（勾选口使能、读写 Flash、只读状态）
```

Hub 不解析 DroneCAN 应用层，对飞控透明。口使能以 Flash 为准，上位机仅改配置。

### 6.1 上位机设计（一期 Python）

**目标：** 地面快速勾选启用几路、读写配置、查看口状态；不做华丽 UI。

| 项 | 选择 |
|----|------|
| 语言 / UI | Python 3 + **CustomTkinter** 或 tkinter（打包可用 PyInstaller → Windows exe） |
| 连接 | Hub **USB-CDC** 虚拟串口（备选：TTL UART） |
| 串口库 | `pyserial` |
| 协议 | **JSON Lines**（一行一条 UTF-8 JSON，`\n` 结尾），便于串口助手对照调试 |

**界面要素：**

1. COM 口选择 + 打开/关闭（波特率固定，如 115200）  
2. 8 路勾选：`CAN_FC, M1…M6, X`；**CAN_FC 默认勾选且禁止取消**  
3. 按钮：读取配置、写入并保存到 Flash、恢复默认（例如仅 FC+M1…M6 开、X 关）  
4. 只读状态区：每口 RX/TX 计数、错误计数、是否故障切断  
5. 日志窗：收发原始 JSON（可选折叠）

**最小命令集：**

| 方向 | 示例 |
|------|------|
| PC→Hub | `{"cmd":"ping"}` |
| PC→Hub | `{"cmd":"get_config"}` |
| PC→Hub | `{"cmd":"set_config","enable":[1,1,1,1,1,1,1,0]}`（顺序：FC,M1…M6,X） |
| PC→Hub | `{"cmd":"get_status"}` |
| Hub→PC | `{"ok":true,"cmd":"get_config","enable":[...],"lock":false}` |
| Hub→PC | `{"ok":true,"cmd":"get_status","ports":[{"tx":0,"rx":0,"err":0,"fault":false},...]}` |
| Hub→PC | `{"ok":false,"err":"locked"}`（飞行锁开启时拒绝 set） |

**安全：**

- Hub 侧：拨码/GPIO「配置允许」或上电后短时窗口；否则 `set_config` 返回 locked  
- 写入成功应答后再提示用户；失败不改本地勾选显示（先读回校准）

**工程目录建议（实现阶段）：**

```
tools/hub_config_gui/
  main.py
  protocol.py
  requirements.txt
  README.md
```

**非目标（一期）：** 固件升级、示波/抓 CAN、多语言、自动找口以外的产测流程。

## 8. 风险

| 风险 | 缓解 |
|------|------|
| FC 口汇聚 12 ESC 带宽 | 测 DroneCAN 实际帧率；必要时降非实时帧或分域（未来） |
| 5×SPI CAN 延迟/丢帧 | DMA、中断优先级、M1/M2 片内；台架压测 |
| isoPower×8 辐射 | AN-0971、分区铺铜、壳体 |
| 与现采转发器行为差异 | 对照现网抓包，保证「只与 FC 互通」一致 |
